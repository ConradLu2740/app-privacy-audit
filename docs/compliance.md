# 合规研判方法（政策 ↔ 行为 ↔ 法规）

目标：把「隐私政策写了什么」和「App 实际做了什么」以及「规则怎么要求」对齐成表，避免空喊违规。

## 1. 三列对照表模板

| ID | 政策原文（摘录） | 实际行为（证据编号） | 规则要点（待核条文） | 一致性 | 风险 |
|----|------------------|----------------------|----------------------|--------|------|
| R-01 | | | | 一致 / 不一致 / 披露不足 / 待核 | 高/中/低 |

**一致性判定：**

- **一致**：政策类型、目的、第三方与观测匹配  
- **不一致**：观测到政策未提及的收集/共享，或政策声称加密但实为明文  
- **披露不足**：有写但过粗（如「可能收集设备信息」未说明标识符与用途）  
- **待核**：证据不足或法规条文未核对原文  

## 2. 政策拆解步骤（C-xx）

1. 在 App 内找到隐私政策入口，保存**版本日期/更新时间**与正文（本地副本，勿提交含账号的导出页）。  
2. 按主题拆条款：  
   - C-01 收集的信息类型  
   - C-02 使用目的  
   - C-03 第三方 SDK / 共享  
   - C-04 存储与期限  
   - C-05 用户权利与注销  
   - C-06 未成年人（如适用）  
3. 给每条可核对句子编号：`C-01-a` 等，便于报告引用。

## 3. 常用规则锚点（引用前务必打开原文核对）

> 下列仅为**检索锚点**，条文以现行有效文本为准；报告中写「已核对日期」。

| 简称 | 全名/文件 | 常见相关点 |
|------|-----------|------------|
| 个保法 | 《中华人民共和国个人信息保护法》 | 告知同意、最小必要、敏感个人信息、单独同意 |
| 网安法 | 《中华人民共和国网络安全法》 | 网络运营者收集使用个人信息 |
| 数安法 | 《中华人民共和国数据安全法》 | 数据安全保护义务 |
| 认定方法 | 《App违法违规收集使用个人信息行为认定方法》 | 未公开规则、强制索权、超范围收集等情形表述 |
| 最小必要规定 | 《常见类型移动互联网应用程序必要个人信息范围规定》 | 分类型 App 的必要个人信息范围 |
| TC260 相关指南 | 移动互联网应用程序（App）收集个人信息相关国家标准/实践指南 | 测试与评估参考 |

**引用格式示例（报告中）：**

```text
《中华人民共和国个人信息保护法》（已核对：YYYY-MM-DD）第 X 条：…
```

禁止：凭记忆编条号、引用已废止表述却不注明。

## 4. 时序合规要点

结合动态时间线关注：

| 场景 | 关注 |
|------|------|
| 首次启动即读标识/定位 | 是否在隐私政策弹窗/同意前 |
| 拒绝权限后仍继续收集 | 是否存在旁路 |
| 「不同意即退出」 | 是否构成强制同意（结合产品形态谨慎表述） |

报告中用事实描述（「在展示政策前已调用 X」）优先于定性口号。

## 5. LLM 使用边界

允许：

- 对长政策做中文摘要草稿  
- 提示「可能相关的检查项」

禁止：

- 让 LLM 直接输出「违法/违规」最终结论  
- 未人工核对就写入条文号  

最终表中每一行由人工负责。

## 6. 修复建议写作

分读者写，避免空话：

| 读者 | 建议方向 |
|------|----------|
| 开发 | 默认关闭非必要采集；标识符用可重置 ID；传输强制 TLS；日志脱敏 |
| 产品/合规 | 政策列明 SDK 与字段；同意分项；提供查询删除入口 |
| 测试 | 用本仓库清单做回归；固定「冷启动/授权路径」用例 |

## 7. 输出位置

- 方法论：本文  
- 单样本对照表：`docs/report/05-compliance-review.md`  
- 证据仍放 `evidence/<package>/`，报告只引用编号与路径
