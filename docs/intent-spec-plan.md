# 题1：Intent → Spec → Plan

> 选题来源：第九届浙江省大学生网络与信息安全竞赛 · 作品挑战赛企业命题  
> 命题企业：浙江省质量科学研究院  
> 赛题原文：`assets/qiye-mingti.docx`  
> **执行定位：不正式参赛，按开源作品集标准做完整项目并发布 GitHub。**

---

## 1. Intent（为什么做、做成什么样）

| 维度 | 决定 |
|------|------|
| 主目标 | **GitHub 作品集项目**：证明「会做 App 隐私合规检测」，可写进简历/面谈 |
| 是否参赛 | **否**。不报名、不交学校盖章、不卡 10-25 竞赛节点 |
| 次目标 | 真正学会 Android 静态/动态/流量三线分析，方法可被他人复现 |
| 非目标 | 不做检测平台、不做多 APP 海量扫描、不追自动化产品化、不写竞赛答辩稿 |
| 人力 | **单人** |
| 起点 | 逆向/Hook/流量均偏新手，靠项目带学习 |
| 交付形态 | **深度检测报告 + 可复现脚本 + 规范仓库** |
| 样本 | **应用商店真实 APP 2–3 款** |
| 成功标准 | ① 仓库结构清晰、README 能让人 30 分钟跑通方法 ② 证据链可复现 ③ 合规引用准确 ④ 技术路径可演示 |

**一句话 Intent：**  
单人把赛题做透，产出一个**可复现、可展示、可讲清楚**的 App 隐私检测 GitHub 项目（报告 + 脚本 + 证据规范），服务作品集与求职，而不是为了交竞赛作品。

---

## 2. Spec（交付什么、边界在哪）

### 2.1 最终交付物（GitHub 优先）

**仓库形态（目标：别人 clone 后能看懂、能复现方法）**

```text
app-privacy-audit/          # 建议仓库名，可再定
├── README.md               # 问题背景、方法总览、快速开始、结果摘要
├── docs/
│   ├── methodology.md      # 三线分析方法与检查清单说明
│   ├── compliance.md       # 政策↔行为↔法规对照方法论
│   └── report/             # 完整检测报告（Markdown 正文 + PDF）
├── checklists/
│   └── privacy-checklist.md
├── scripts/
│   ├── frida/              # Hook 脚本（按敏感点拆分）
│   ├── static/             # 静态辅助脚本（可选）
│   └── traffic/            # 过滤/导出辅助（可选）
├── evidence/               # 脱敏证据（按 APP 分目录）
│   └── <app_package>/
│       ├── static/
│       ├── dynamic/
│       └── traffic/
└── assets/                 # 截图、架构图等（非敏感）
```

1. **主交付：检测报告**  
   以 Markdown 为主（GitHub 友好），可导出 PDF。结构对齐赛题四维（见 2.3）：
   - 样本清单与版本（包名、versionName/Code、渠道、哈希）
   - 静态：权限、敏感 API/SDK、明文存储线索
   - 动态：运行时敏感行为（日志/截图/Hook）
   - 流量：时间线、明文/弱加密（过滤条件 + 关键字段）
   - 合规：政策关键句 vs 实际行为 + 法规条款
   - 风险分级 + 修复建议

2. **证据规范（脱敏后入库）**
   - 编号体系：`E-<app>-<line>-<n>`（如 `E-app1-dyn-03`）
   - 每条证据：结论一句话 + 复现步骤 + 文件路径
   - **不上传**：完整 APK、用户隐私原文、未脱敏 PCAP 中的账号/token
   - PCAP 只留关键流摘录或脱敏截图；脚本可公开

3. **演示资产（可选，增强作品集）**
   - README 顶部结果摘要表 + 1 张方法架构图
   - 有余力再做 3–5 分钟演示录屏（放 README 外链或 Release）

### 2.1.x 与竞赛的切割

- 不使用竞赛官方报告模板作为唯一格式；方法论仍对齐其评分四维（利于讲清深度）
- 不维护报名/盖章/缴费/钉钉群等竞赛流程
- 若日后想参赛，报告可再套官方模板，**不阻塞当前仓库**

### 2.2 明确不做（YAGNI）

- 不做 Web 控制台 / 自动上传 APK 平台  
- 不做全商店扫描、不做大规模爬虫  
- 不自研检测引擎；工具链以 Frida + Jadx + 抓包为主  
- 不碰需要 root 的深度内核方案（新手风险高、时间不够）  
- 不把「LLM 自动合规」做成核心系统；**LLM 只作研判辅助**

### 2.3 深度标准（源自赛题评分，作品集仍按此打磨）

| 维度 | 权重参考 | 本项目打法 |
|------|----------|------------|
| 技术分析完整度 | 30% | 静态+动态+流量**三线全开**，每款 APP 同一检查清单，可横向对比 |
| 合规判断准确性 | 30% | 「政策条款 ↔ 运行时行为 ↔ 法规条文」三列对照；引用《个保法》等**具体条款号** |
| 证据充分性 | 20% | 每条结论：截图/日志/包名+类名+方法/PCAP 过滤条件；编号可追溯 |
| 创新性与深度 | 20% | ① 三线证据交叉验证 ② LLM 做政策一致性初筛+人工复核 ③ 2–3 款横向对比 |

### 2.4 样本选择 Spec

选 **2–3 款**，满足：

- 应用商店可公开下载、用户量中等以上  
- 至少 1 款有较完整隐私政策文本  
- 覆盖不同风险画像：如 1 款工具类、1 款社交/内容类、1 款生活/电商类  
- **避免**：金融/强加固壳、纯游戏  

> 包名在 Week 1 锁定；锁定后尽量不换（换样成本高，且破坏方法一致性）。

### 2.5 技术栈（新手可落地）

| 环节 | 工具 | 用途 |
|------|------|------|
| 模拟器 | 夜神/MuMu/雷电（Android 9–11） | 可控环境 |
| 静态 | Jadx-gui（+ apktool 可选） | 反编译、搜敏感 API |
| 动态 | Frida（+ objection 可选） | Hook 设备标识/定位/通讯录等 |
| 流量 | 模拟器代理 + mitmproxy/Charles；或 PCAPdroid | 抓 HTTP/HTTPS |
| 证书 | 系统信任用户证书 / SSL unpinning | HTTPS 解密（写进环境说明） |
| 合规辅助 | LLM 可选 | 政策摘要、条款匹配草稿，**人工必审** |
| 文档 | Markdown 为主 | GitHub 友好；可再导 PDF |

### 2.6 验收清单（DoD · GitHub 作品集标准）

- [ ] 2–3 款 APP 均完成同一检查清单  
- [ ] 每款至少 5 条可复现敏感行为证据（含 ≥1 条流量侧）  
- [ ] 合规对照表覆盖：权限、收集目的、第三方共享、存储/传输（缺项写明局限）  
- [ ] 法规引用带条款号，无臆造条文  
- [ ] `scripts/` 可按 README 在 30 分钟内跑通至少 1 条动态证据  
- [ ] 证据全部脱敏；仓库可公开  
- [ ] README 含：问题、方法图、样本表、发现摘要、复现步骤、局限与后续  
- [ ] 已推送到 GitHub（public），commit 历史可读

## 3. Plan（约 6 周 · 单人 · 无竞赛死线）

> 今天约 2026-09-14。质量优先于赶节点。Week 0 可与 Week 1 并行。

### Week 0 仓库骨架

- [ ] 建 GitHub 仓库，按 2.1 目录结构初始化  
- [ ] README 草稿 + LICENSE（MIT 或 Apache-2.0）  
- [ ] `.gitignore`（忽略 APK、原始 PCAP、未脱敏日志）  
- **产出：** 空项目可 clone  

### Week 1（9/14–9/21）环境 + 选样 + 清单定稿

- [ ] 装模拟器、Jadx、Frida、抓包代理；打通「装 APP → 能抓到 HTTPS」  
- [ ] 试分析 1 款练手 APP（开源/低加固）  
- [ ] 锁定正式样本 2–3 款，记录包名/版本/哈希  
- [ ] 写出**统一检查清单 v1**  
- **产出：** methodology 草稿 + 样本表 + `checklists/`  

### Week 2（9/22–9/28）静态分析打底

- [ ] 每款：权限清单、敏感 API 搜索、疑似 SDK  
- [ ] 假设列表 H-xx；隐私政策拆成条款 C-xx  
- **产出：** 静态章节 + `evidence/*/static/`  

### Week 3（9/29–10/5）动态 Hook 验证

- [ ] Frida 最小脚本：IMEI/设备标识、定位、通讯录、剪贴板等  
- [ ] 验证 H-xx；日志/截图入库  
- **产出：** `scripts/frida/` + `evidence/*/dynamic/`  

### Week 4（10/6–10/12）流量与明文传输

- [ ] HTTPS 中间人或 PCAPdroid  
- [ ] 行为↔请求时间线对齐  
- **产出：** 流量章节 + `evidence/*/traffic/`（脱敏）  

### Week 5（10/13–10/19）合规研判 + 报告成稿

- [ ] 政策 vs 行为 vs 法规三列对照（LLM 草稿人工审）  
- [ ] 风险分级 + 修复建议  
- **产出：** `docs/report/` 完整稿  

### Week 6（10/20–10/27）打磨 + 公开发布

- [ ] 自检 DoD；补证据；统一术语  
- [ ] README 结果摘要 + 方法图  
- [ ] 推 GitHub；打 `v1.0` tag  
- **产出：** 可公开作品集仓库  

### 风险与缓冲

| 风险 | 应对 |
|------|------|
| HTTPS 解不开 | 优先明文 HTTP + 设备侧抓包；报告写清局限 |
| APP 加固反编译失败 | Week1 筛样避开；换样只在 Week1 |
| 时间不够 | 砍到 2 款做透，优于 3 款做浅 |
| 法规引用出错 | 只写核对过的条文；存疑标「待核」 |
| 误提交敏感数据 | 证据入库前脱敏；APK/原始流量永不进库 |
