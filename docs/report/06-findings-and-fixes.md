## 2. 分样本结论

### A1 墨迹天气

- **做得好的：**
  - 定位权限与天气核心功能匹配
  - 未声明通讯录/短信/READ_PHONE_STATE
  - 静态分析可完整进行

- **主要问题：**
  - 后台定位 + 活动识别属于扩展权限面，需政策显著说明
  - OAID 采集体系庞大（323 文件命中），涉及多个厂商 SDK
  - 第三方 SDK（友盟/个推/穿山甲/高德/百度）共享范围未验证

- **未证实但值得关注：**
  - 动态行为（壳阻断）
  - 流量端点（首启受阻）
  - 政策一致性（政策正文不可得）

### A2 豆瓣

- **做得好的：**
  - 隐私政策披露较完整（设备标识、应用安装信息、剪贴板、精确定位均有说明）
  - 精确定位限制在「地点签到」场景，声明不存储
  - 剪贴板声明「仅本地识别，不上传」
  - 流量观测仅自有域名，未见第三方 SDK 触发

- **主要问题：**
  - `QUERY_ALL_PACKAGES` 虽已披露，但「应用安装信息」的实际采集范围需验证
  - 剪贴板「不上传」声明需动态 hook 验证

- **未证实但值得关注：**
  - 登录后可能触发的第三方 SDK 上报
  - 自研埋点 `amonsul.douban.com` 的具体数据内容

### A3 NewPipe

- **做得好的：**
  - 权限极少，无定位/电话/通讯录/OAID 簇
  - 动态 30s 剧本：敏感 API 均未观测到
  - 流量仅 `www.youtube.com`，无第三方追踪
  - GDPR 政策与观测一致

- **主要问题：**
  - 崩溃上报路径未实测（可能未触发）

## 4. 方法层收获（作品集叙事可用）

- **三线交叉如何减少误报：** 静态命中 ≠ 运行时调用；动态未观测 ≠ 不存在；流量仅域名级 ≠ 载荷安全。三线互相验证才能下结论。
- **性价比最高的检查项：** 权限清单（aapt 一行命令）、敏感 API 文件计数（rg 统计）、连接级流量（PCAPdroid 免 root）。
- **单人项目时间分配：** 静态 40% / 动态 30% / 流量 20% / 政策与报告 10%。商业壳 App 的动态成本极高，建议优先开源样本做动态闭环。
